This note records the first bare =SU(2)_2= colored framed link evaluator core.  It is a
restricted evaluator over the currently machine-readable =LinkDiagram= schema.  It is not a
Kirby-color implementation, not a twisted-color formula, not ordinary surgery, not a closed
4-manifold invariant, and not exotic-pair evidence.

* API Contract

The public entry point is:

#+begin_src python
evaluate_su2_level2_link(diagram: LinkDiagram, labels_by_component: Mapping[str, str])
#+end_src

It returns a deterministic JSON-ready dictionary.  Supported cases return =status: pass= and a
value of shape:

#+begin_src text
coefficient_times_twist
  coefficient: Q(sqrt2)
  twist: zeta_16^exponent
#+end_src

Unsupported diagram features return =status: blocked= with a structured =blocker= object.  Bad
label maps or unknown =SU(2)_2= labels are rejected as invalid input.

* Supported Controls

All of the following go through the same evaluator entry point:

- empty link: value \(1\).
- colored no-crossing split links: product of quantum dimensions and framing twists.
- framed unknot: included as the one-component no-crossing case.
- positive 0-framed Hopf-shaped crossing controls: value \(S_{ij}/S_{00}\), recorded as a
  =Q(sqrt2)= coefficient with trivial framing twist in the current fixtures.

The Hopf path is selected from diagram shape and sanity checks, not fixture id.  The accepted
crossing-bearing shape is still narrow: exactly two undotted components, zero framings, two
positive inter-component crossings, and linking matrix \(\begin{pmatrix}0&1\\1&0\end{pmatrix}\).

* Framing Convention

Every evaluator output records:

#+begin_src text
multiply by theta_label^framing for each component
#+end_src

with =SU(2)_2= twists represented by =zeta_16= exponents:

- label =0=: exponent =0=
- label =1=: exponent =3=
- label =2=: exponent =8=

The positive-framing sign remains =SOURCE NEEDED/local-convention=, inherited from the upstream
RT/Kauffman convention ledger.  The evaluator preserves this boundary in output metadata.

* Structured Blockers

The core blocks rather than guesses when the current schema is insufficient.  In particular, a
general crossing diagram receives =reason_id: general-crossing-diagram-unsupported= because
=LinkDiagram= currently records signed over/under crossings but not full planar adjacency,
F-symbol gauge, or R-symbol convention data.

Dotted components receive =reason_id: dotted-components-unsupported= because dotted Kirby
semantics belong to later Kirby/surgery nodes, not to the bare colored framed link evaluator.

* Downstream Gate Meaning

This should let =n18-colored-framed-link-evaluator-gate= upgrade from a fixture-control gate to a
restricted evaluator-core gate: downstream code can call one evaluator entry point for elementary
and Hopf controls.

It should not unblock Kirby color, ordinary surgery, twisted/decorated formulas, closed
4-manifold claims, or exotic input work by itself.  Those remain downstream graph nodes.
