This node creates the minimal decorated-core input artifact needed by later
candidate-validation work.  It aligns:

- a machine-readable =LinkDiagram=;
- a supported finite group \(A\), currently trivial and \(Z/2\);
- component decoration metadata from =n34=;
- candidate \(\Omega_a\) sector/coefficient metadata from =n33=.

It is not a theorem, not a link evaluator, not a Kirby color sum, not a
decorated Kirby-move proof, not a closed invariant, and not an exotic-pair
computation.

The artifact also contains an exact =link_evaluator_call_plan=.  This plan is
only a scaffold: it enumerates the finite list of labels and coefficient
products that would be sent to the accepted restricted
=evaluate_su2_level2_link= entry point.  It deliberately records
=does_execute_link_evaluator: false=.

* Component-to-Sector Mapping

For each component decoration, n35 maps the finite-group element label to the
same sector id in the n33 =omega_a_candidate_certificate(group)= artifact.

Current \(Z/2\) behavior:

- zero decoration =0= maps to sector =0= with all character values \(1\);
- nonzero decoration =1= maps to sector =1=, where the current local
  \(SU(2)_2\) assignment has character values \(1,-1,1\) for labels \(0,1,2\).

This is a candidate coefficient metadata alignment only.  The coefficient
certificate remains =candidate-experimental / NOT PROVED IN REPO / SOURCE
NEEDED= and does not certify a homologically twisted Kirby color.

* Expansion Plan

For a diagram with \(k\) components, n35 forms the \(3^k\) formal
=SU(2)_2= label assignments over simple labels =0,1,2=.  Each term records:

- =labels_by_component=, the labels that would be passed to the restricted
  colored framed link evaluator;
- =coefficient_factors= copied from the component's candidate \(\Omega_a\)
  sector;
- =coefficient_product= in exact \(Q(\sqrt 2)\) JSON;
- =planned_call.function= set to
  =twisted_yetter.su2_link_evaluator.evaluate_su2_level2_link=.

This is a finite expansion scaffold, not an evaluated sum.  A later node may
consume it to call the restricted evaluator and then decide whether a sector
passes or is blocked.  n35 itself never treats a planned term as a link value.

* Toy Fixtures Covered

Tests cover:

- =s4-empty.json= with trivial \(A\) and explicit empty/zero decoration;
- =cp2-plus-one-framed-unknot.json= with \(Z/2\) zero decoration;
- =cp2-plus-one-framed-unknot.json= with \(Z/2\) nonzero decoration;
- =s2x-s2-hopf-zero-framed.json= with component decorations aligned to
  component order even when supplied as an unordered mapping.

The tests also check deterministic JSON round-trip serialization and the
absence of float markers such as =.0= in the serialized artifact.

The reproducible artifact bundle currently records:

- empty \(S^4\) with trivial \(A\), term count \(1\);
- \(CP^2\) with \(A=Z/2\), nonzero decoration, term count \(3\);
- \(S^2 \times S^2\) Hopf toy diagram with mixed \(Z/2\) decorations, term
  count \(9\).

* Trust Boundary

The API refuses high claims by explicit flags or unsupported claim levels.
Allowed claim levels are only:

- =computed evidence scaffold=;
- =provisional-low-confidence=;
- =candidate-experimental=.

The artifact explicitly records =does_not_compute=:

- link evaluation;
- Kirby color sum;
- decorated Kirby move proof;
- closed invariant;
- exotic detection.

Therefore n35 does not pass any of the later mathematical gates by itself.

* Unblocks and Remaining Blockers

Unblocks:

- =n36-many-case-candidate-validation-suite= can consume deterministic
  decorated-core input artifacts instead of guessing how component decorations
  map to candidate sectors.
- later test generators can build CP2 and S2xS2 toy cases with exact
  component-to-sector metadata.

Still blocked:

- source-audited Yetter \(Z/2\) decoration rule;
- general finite \(A\) theorem-level \(\Omega_a\) formula;
- actual link evaluation and Kirby color summation for decorated inputs;
- handle-slide / basis-change / decorated Kirby-move proof;
- ordinary surgery gate =n24=;
- toy closed suite =n55=;
- exotic input certification and exotic computation.
