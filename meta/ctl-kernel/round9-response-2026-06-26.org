* Fixed In This Round

** InvalidHistory / UnsupportedProfile 分層

之前 =validate_batch_common= 在 evidence 看到 unsupported basis 時太早回報
=UnsupportedProfile=。現在改成：

- batch 內部 structural checks 先跑完；
- transition-specific structural checks 先跑完，例如 =set target not recorded=、
  =evidence CID not recorded=；
- 之後才回報 unsupported evidence basis。

因此：

#+begin_example
invalid binding target + unsupported evidence basis -> InvalidHistory
#+end_example

** Batch-level scalar checks 提前

=principal_claim=、=submitted_by=、=admitted_at= 現在會在 recorded Revision payload
profile validation 前先檢查。

因此：

#+begin_example
bad admitted_at + unsupported recorded profile -> InvalidHistory
#+end_example

這不是把 unsupported profile 吃掉，而是承認 malformed batch timestamp 是可靜態判定的
protocol invalidity，應比「某個 recorded payload profile 是否支援」更早分類。

** authentication_assurance 正式變成 id

=principal_claim.authentication_assurance= 仍是 optional field，但若存在，必須通過
=is_id=。例如 =Local Operator= 不合法，因為有空白與大寫。

** Policy selector host exception 關閉

PolicySet 裡的 =resources= 每個 selector 現在必須先是 object，才會讀 =keys()=。
因此 malformed selector 會回 =InvalidHistory=，不會冒出 Python =AttributeError=。

** agent/run-receipt/1 最小 payload profile

我同意 Round 9 audit 指出的 inconsistency：

#+begin_example
SUPPORTED_EVIDENCE_BASIS contains agent/run-receipt/1
but SUPPORTED_PAYLOAD_PROFILES did not.
#+end_example

這輪沒有移除 run-receipt basis，而是補上一個 deliberately minimal 的
=agent/run-receipt/1= Revision profile：

- =revision_kind= 必須是 =run-receipt=；
- payload 必須至少含 =status=；
- =status= 只能是 =ok= 或 =failed=；
- optional =command= 必須是 string array；
- optional =started_at= / =finished_at= 必須是 canonical timestamp。

這不是宣稱 run receipt 的完整 semantic attestation 已完成；只是把「支援的 evidence
basis」和「可 structural-validate 的 payload profile」對齊，避免出現半支援狀態。
