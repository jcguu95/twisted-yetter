* 狀態

這個目錄是 =CTL Kernel v0.1.1 Experimental Freeze= 之後的第一個 dogfood area。

目前採用：

#+begin_example
shadow mode
#+end_example

意思是：

- 現有 =org/wiki= 與 repo 文件仍是人類可讀的 source of truth。
- 這裡只保存 repo-local canonical admission metadata。
- 這裡的 objects 先治理 CTL Kernel / ResearchCTL meta decisions。
- 暫時不把 twisted-Yetter 數學主線研究記憶搬進來。

* 為什麼先 shadow mode

直接把 twisted-Yetter 主線研究放進 CTL 會同時引入三種風險：

- kernel dogfood 風險；
- ResearchCTL profile 尚未成熟的 migration 風險；
- 數學研究 artifact 本身的長期保存風險。

所以第一階段只記錄低風險 meta decisions，例如：

- v0.1.1 experimental freeze acceptance；
- dogfood policy changes；
- v0.1.2 backlog decisions；
- profile design decisions；
- future migration gates。

* 重現

從 repo root：

#+begin_src sh
cd meta/ctl-dogfood
uv run python scripts/verify.py
#+end_src

=verify.py= 只從已寫入的 objects / refs / manifest 重新載入、重算 CID、replay chain。

若要從零重建 bootstrap snapshot，才使用：

#+begin_src sh
cd meta/ctl-dogfood
uv run python scripts/bootstrap.py --force
uv run python scripts/verify.py
#+end_src

=bootstrap.py --force= 會覆寫目前 bootstrap objects / refs / manifest；未來累積更多 dogfood
transitions 後，不應把它當成日常指令。

* 第一個 Admitted Decision

第一個 transition 記錄：

#+begin_quote
接受 =CTL Kernel v0.1.1 Experimental Freeze=，並以 shadow mode 開始 dogfood。
#+end_quote

這不是把 CTL 當成 production security boundary，也不是把 twisted-Yetter 主線研究正式搬入 CTL。

* Graduation Gate

在進入 twisted-Yetter 研究主線前，至少先完成：

- 5-10 個低風險 meta decisions 的 CTL admission；
- 每次都可用 =scripts/verify.py= 重建 current root；
- 明確列出 v0.1.2 migration / patch 需求；
- 決定 ResearchCTL profile 的最小 object schema。
