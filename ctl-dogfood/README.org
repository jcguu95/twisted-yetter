* Current Graph Projection

append-only history 不應污染日常閱讀。預設請使用 current-view tool：

#+begin_src sh
cd ctl-dogfood
UV_CACHE_DIR=/Users/jin/data/local/projects/twisted-yetter/.uv-cache uv run python scripts/show_current_graph.py
#+end_src

若需要機器可讀輸出：

#+begin_src sh
cd ctl-dogfood
UV_CACHE_DIR=/Users/jin/data/local/projects/twisted-yetter/.uv-cache uv run python scripts/show_current_graph.py --json
#+end_src

這個工具最後可能應該移入 =ctl-meta=，因為所有 CTL dogfood project 都需要 current
projection。但目前先留在本 repo；不要為了這個研究 graph 去修改 =ctl-meta=。

為了之後容易拆分，graph payload 明確保存：

- =graph_identity.graph_namespace=
- =graph_identity.graph_id=
- =split_policy.portable_split_key=
- node / edge ids

若未來 graph 變多或 governance 需要分離，可以依這些欄位把同一 graph 的 objects 搬到
graph-specific store，同時保留原 CID 作為外部 reference。

Append-only enforcement 目前分成幾層：

- CTL objects 用 content-addressed CID；若底層 object JSON 被改，=verify.py= 會因 CID
  filename / bytes 不一致而失敗。
- =refs/main= 是 mutable pointer，但 =verify.py= 會從 pinned genesis replay 到 current root。
- graph update 不是改舊 object，而是建立新的 =ctl/revision/1=，其 =parents= 必須包含上一個
  active graph revision；=verify.py= 會檢查 admission manifest 的 fast-forward 關係。
- admission manifests 必須指向 current chain 上可 reach 的 root；舊 manifest/root 不應被改寫或丟失。
- filesystem 本身不是防竄改資料庫，所以最後一層仍由 Git history 和 verify transcript 承接。

* Reproduce

日常驗證：

#+begin_src sh
cd ctl-dogfood
uv run python scripts/verify.py
#+end_src

若本機 sandbox 不允許寫入預設 =uv= cache，可使用 repo-local cache：

#+begin_src sh
cd ctl-dogfood
UV_CACHE_DIR=/Users/jin/data/local/projects/twisted-yetter/.uv-cache uv run python scripts/verify.py
#+end_src

append decision graph：

#+begin_src sh
cd ctl-dogfood
uv run python scripts/admit_graph.py --update
uv run python scripts/verify.py
#+end_src

從零重建 bootstrap snapshot：

#+begin_src sh
cd ctl-dogfood
uv run python scripts/bootstrap.py --force
uv run python scripts/verify.py
#+end_src

=bootstrap.py= 預設拒絕覆寫既有 store；只有 =--force= 會重建 snapshot。
